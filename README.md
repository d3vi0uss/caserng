# DropLab — Skin RNG Simulator

A fully client-side Counter-Strike-inspired skin RNG and collection simulator. It runs in a browser and can be hosted as a static GitHub Pages site.

## Features

- Three sequential RNG layers: weapon, skin finish, and supported pattern.
- Effective odds are calculated from the actual normalized selection weights and displayed as `1 in X` for each layer and the combined drop.
- Single rolls, unlockable x2 / x5 / x10 batches, auto-roll, and configurable auto-roll stop conditions.
- Float values, wear grades, pattern seeds, pattern multipliers, and rarity-based reveal effects.
- Original vector weapon illustrations with visual finish colors, pattern variation, and float wear marks. No third-party image files are required.
- Inventory search, filters, sorting, favorites, locks, inspection, individual selling, and bulk selling.
- Five equipment slots that generate passive income, plus capped offline earnings.
- Permanent upgrades for weapon luck, finish luck, pattern luck, income, offline earnings, item value, rolling, automation, and storage.
- Collection index for finishes and supported pattern variants, daily quests, lifetime achievements, rotating local events, a simulated market, charts, and statistics.
- Autosaving to localStorage and IndexedDB, plus JSON save export/import and reset controls.
- Responsive layout for desktop, tablet, and mobile browsers.
- Service worker and web app manifest for offline use after the first successful load.

## Add it to GitHub

1. Download and unzip this project.
2. Open your GitHub repository. Create a new repository if you do not already have one.
3. Upload **all files and folders in this project** to the repository's top level. `index.html` should be in the repository root, not inside an extra nested folder.
4. Commit the files to the `main` branch.
5. In the repository, open **Settings → Pages**.
6. Under **Build and deployment**, choose **Deploy from a branch**.
7. Choose branch **main** and folder **/(root)**, then save.
8. Open the Pages URL GitHub shows. The first load needs an internet connection; after the app shell is cached, supported pages can load offline.

When you update the project, upload the changed files and commit again. GitHub Pages will publish the new version.

## Run it locally

You can open `index.html` directly for basic testing. For service-worker/offline testing, use a local static server (service workers require `localhost` or HTTPS). For example:

```bash
python3 -m http.server 8000
```

Then open `http://localhost:8000`.

## Important implementation notes

### How the displayed odds work

The data file's `odds` values are **relative rarity weights**, not separate unconditional probabilities. A single categorical selection cannot assign every possible outcome an independent `1 in X` probability unless all probabilities sum to 100%. DropLab therefore normalizes the weights for the currently available options at each stage. The game then displays the inverse of the resulting probability as `1 in X`.

The weapon, finish, and (where supported) pattern stages are sequential and conditionally independent. The combined probability is:

`P(weapon) × P(finish | weapon) × P(pattern | finish)`

The combined `1 in X` value is the inverse of that product. Luck upgrades and active local events change the weights first; the UI's effective odds are recalculated from the same values used by the roll engine.

### Assets and naming

This repository uses original inline SVG artwork generated by the game code. It does not bundle official Counter-Strike models, textures, logos, or game files. Weapon and finish names are descriptive references for this fan-made simulator; DropLab is not affiliated with or endorsed by Valve or Counter-Strike.

### Saves and privacy

There is no backend, no account system, and no external API. Save data remains in the browser profile where you play. Browser data clearing can erase local progress, so use **Settings & Saves → Export Save** to make backups. Import a JSON backup on another browser/device to transfer progress.

The simulated market, rotating events, prices, global-style announcements, and offline earnings are local game mechanics. They do not connect to real players, real markets, or an online game service.
